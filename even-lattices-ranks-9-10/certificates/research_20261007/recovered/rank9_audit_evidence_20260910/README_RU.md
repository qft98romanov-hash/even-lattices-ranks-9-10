# Аудит определителя в ранге девять: дополнительные материалы

Конфиденциальные исследовательские материалы. Дата аудита: 10 сентября 2026.

Пакет содержит результаты повторного теоретического, программного и
вычислительного аудита оценки

    det(L) >= 21870

для положительно определённых чётных целочисленных решёток ранга девять
с минимумом квадрата нормы не меньше шести, а также примера K9,
достигающего этой оценки.

## Результат и границы проверки

Все обязательные верификаторы исходного пакета прошли свежий запуск в
изолированной копии. Нижний флаг до ранга шесть и все блоки ранга семь
действительно перечислены заново; результаты побайтно совпали с исходными.
Проверка не ограничивалась чтением старых сообщений PASS. Восстановленный
исходный архив оставлен без изменений.

При этом аудит выявил настоящую ошибку общего вспомогательного алгоритма
и несколько недостатков изложения. Проверка центрированных вычетов
пропускала ненулевой слой нулевого класса m=h, где h — порядок класса
дискриминантной группы. Нужно дополнительное условие h^2*s >= 6.
Явный регрессионный пример показывает, что вне фактически используемых
ветвей старый алгоритм может принять расширение с минимумом два. Для
четырёх фактических родителей ранга семь дискриминантные радиусы дают
s >= 6-93/22 = 39/22 > 3/2 при h>=2, поэтому h^2*s>6 выполняется
автоматически. При h=1 первый слой даёт s>=6. Пропуск не меняет итоговую
оценку в ранге девять.

Отдельная исправленная копия `verify_rank7_topdown_hardened.py` добавляет
ровно эту недостающую проверку; остальные изменения — поясняющие комментарии.
Приложен точный diff. Полный свежий прогон исправленной ветви завершился
успешно, а его протокол побайтно совпал с исходным. Исходный архив сохранён
как точная запись прежнего состояния. Решётка со старой меткой `4 E7*`
имеет матрицу Грама 4 C_E7^{-1} и при обычном евклидовом масштабировании
равна **2 E7***. Отчёты объясняют эту поправку и необходимые уточнения
терминов и условий утверждений.

Предмет пакета — задача об определителе в ранге девять и соответствующая
цепочка сертификатов. Здесь не проверяются все результаты исходного
препринта, его вложения в объемлющие решётки ранга 48, глобальная
оптимальность упаковок, кластеры, единственность K9 или задачи ранга десять.
В математических отчётах указаны используемые классические теоремы и
точные границы приложения к упаковкам.

## Воспроизведение

Нужен обычный CPython 3 без флага `-O`: операторы assert являются частью
проверок. Сторонние пакеты Python не требуются. Из корня этого пакета:

```bash
sha256sum -c SHA256SUMS
bash run_audit_checks.sh
```

Общий сценарий запускает четыре новые проверки и исправленную ветвь:

1. `test_enumeration_independent.py`: независимое перечисление в
   ограничивающем координатном параллелепипеде; 10000 интервальных тестов,
   36 граничных тестов с большими центрами, 100 рациональных эллипсоидов,
   60 определителей, точные минимумы классов малых рангов и полные списки
   расширений из ранга один в два и из ранга два в три.
2. `branch_independent_checks.py`: 51 независимое сравнение перечислений,
   точные тождества для корневых отражений, прямые проверки минимумов и
   независимо вычисленные определитель и минимум K9.
3. `verify_theory_and_sharpness.py`: точная арифметика окон Эрмита,
   оценок поднятия и прозрачное доказательство точности K9 через 64 точки
   в заданном классе вычетов; исходные модули не импортируются.
4. `topdown_zero_layer_regression.py`: диагональный пример с полной
   таблицей из 28512 дискриминантных классов; старый алгоритм принимает
   ошибочный кандидат, исправленный исключает его.
5. `verify_rank7_topdown_hardened.py`: точный повторный запуск затронутой
   ветви после добавления пропущенного условия.

Для повторения **полной проверки исходных сертификатов** и **полного
перечисления** используйте отдельную копию: некоторые верификаторы
перезаписывают детерминированные отчёты.

```bash
cp -R audit_20260910/rank9_complete_certificates /your/scratch/rank9-replay
cd /your/scratch/rank9-replay
bash run_all_checks.sh
bash run_full_regeneration.sh
```

Замените `/your/scratch/rank9-replay` новым доступным для записи каталогом.
Подробные команды даны в исходных README и RUN_ORDER. Сценарий полного
перечисления сам создаёт и удаляет временный каталог генерируемых данных.
Дополнительный полный cross-check E6 является факультативным; при новом
аудите он не запускался. Нужные для доказательства выводы проверены
специализированными программами для E7 и H6318.

## Независимые проверки и повторный запуск исходного алгоритма

Полный большой поиск намеренно повторяет исходный генератор. Новые
независимые реализации проверяют указанные арифметические ядра, расширения
малых рангов, отдельные ветви и доказательство точности через 64 точки.
Они не составляют отдельной реализации всего поиска ранга семь. Отчёты
разделяют доказательство полноты, чтение кода, независимые тесты, полную
регенерацию и проверку каждой ветви.

При одновременном выполнении время исходного обязательного сценария
составило 252.900911 секунды, полной регенерации — 230.929221 секунды.
Среда: CPython 3.12.14, Linux x86_64, assert включены. Это времена
конкретного аудита, а не изолированный тест производительности. Оба
сценария завершились с кодом 0 и итоговыми маркерами
`ALL_RELEASED_EXACT_CERTIFICATES_PASS` и
`FULL_EXACT_REGENERATION_BYTE_IDENTICAL`. Все 83 исходные контрольные
суммы совпали до и после запуска. Пять файлов raw нижнего флага также
дополнительно сравнены побайтно и полностью совпали.

Строка `generator rerun = False` в конце журнала регенерации относится
только к последнему статическому верификатору. Предшествующие строки
фиксируют настоящее новое перечисление и побайтные сравнения.

## Состав и целостность

* `audit_20260910/`: отчёты по теории, перечислению, ветвям и воспроизведению;
  новые программы, свежие протоколы, исправление, метаданные и локальные хеши.
* `audit_20260910/rank9_complete_certificates/`: неизменённый распакованный
  исходный пакет; относительные пути для импортов сохранены.
* `recovered/rank9_complete_certificates.zip`: точный исходный ZIP с SHA-256
  `608cf4b022d448476028d56f002485ec39c1893b2a2e797458838c64db11d8b3`.
* `manuscripts/`: окончательная английская рукопись (31 страница PDF) и
  русская рукопись (41 страница PDF); каждая представлена исходником LaTeX
  в `.txt` и готовым PDF. Все четыре файла также выдаются отдельно.
  Отчёты включают заключительную математическую проверку рукописей;
  дополнительные `RU_appendix64_extracted.py` и `.transcript` фиксируют
  успешный запуск проверки 64 точек, извлечённой из русского приложения.
* `SHA256SUMS`: общий список хешей всех обычных файлов, кроме самого списка.

Исходный manifest сертификатов проверяется из корня его пакета,
`replay_evidence_SHA256SUMS` — из `audit_20260910/`, а
`topdown_hardening_sha256.txt` — из корня дополнительного пакета.
Общий manifest позволяет проверить все файлы одной командой.

Абсолютные временные пути в исторических журналах описывают среду
прошедшего запуска; для переносимого повторения программ они не нужны.
Для использования любого LaTeX-файла `.txt` в Overleaf скопируйте всё
его содержимое в `main.tex` и выберите компилятор **XeLaTeX**. Русский и
английский исходники — самостоятельные полные документы. Рядом включены
готовые к чтению PDF.
